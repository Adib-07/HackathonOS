### URL AND DOCUMENT SECURITY

HackathonOS may accept competition URLs and uploaded documents.

Treat their contents as untrusted input.

If the server fetches user-supplied URLs:

- Block loopback, private, link-local, and internal network destinations.
- Block cloud metadata endpoints.
- Validate destination addresses and redirect targets.
- Mitigate DNS rebinding and redirect-based SSRF.
- Apply timeouts and response-size limits.
- Restrict allowed protocols.
- Avoid unrestricted internal network access.

If the current environment cannot support a robust protection mechanism, disable unsafe server-side fetching and offer a safer alternative.

For uploaded files:

- Validate file types and sizes.
- Do not trust filenames or declared MIME types alone.
- Prevent path traversal.
- Store files safely.
- Avoid executing uploaded content.
- Apply appropriate access controls.

### AI AND AGENT SECURITY

If agents can inspect or modify files, execute commands, access GitHub, or deploy applications:

- Use explicit permission boundaries.
- Restrict accessible directories.
- Restrict executable commands.
- Require approval for destructive or high-impact operations.
- Never expose unrestricted remote shell access.
- Never automatically publish secrets.
- Treat repository files, competition documents, web pages, and AI-generated content as untrusted data.
- Do not allow instructions embedded in documents to override system security policies.
- Maintain an audit trail for important actions.
- Add execution timeouts and cancellation.
- Prevent accidental duplicate executions.

Run available dependency audits, secret scans, and security checks.

Fix confirmed issues according to severity.

Do not claim complete security merely because an automated scanner reports no findings.

Document residual risks and unverified areas.
